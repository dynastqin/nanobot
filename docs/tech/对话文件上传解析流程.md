# 技能积累

## nanobot 文件上传与解析机制

### 结论

nanobot 对上传文件的解析**不是**通过 Skill 或 MCP 工具完成的，而是**硬编码在 Agent Loop 的消息预处理流程中**，在消息到达 LLM 之前自动处理。所有文件类型共享同一条上传链路，但在预处理阶段按类型分流。

### 统一上传链路（所有文件类型相同）

```
用户选择文件（WebUI）
    │
    ▼
前端 useDocuments.ts / useAttachedImages.ts
    │ FileReader.readAsDataURL() → base64 data: URL
    │ （不做任何内容解析，仅编码传输）
    ▼
ThreadComposer.tsx (L1448-1464)
    │ 合并 image + document 为统一 media 数组
    │ 格式: { data_url: "data:...;base64,...", name: "xxx" }
    │ 通过 WebSocket 发送
    ▼
websocket.py (L600-675) _decode_media()
    │ 校验 MIME 白名单 + 文件大小上限
    │ save_base64_data_url() → base64 解码写入磁盘临时文件
    ▼
loop.py:1402 AgentLoop._prepare_message_media()
    │ 判断 channels_config.extract_document_text 开关
    │ 调用 extract_documents(content, media_paths)
```

### 预处理分流（extract_documents 之后）

`extract_documents()` (`document.py:274`) 是分流点，按文件类型走不同路径：

```
extract_documents(content, media_paths)
    │
    ├─ 图片 (png/jpeg/webp/gif)
    │     → 保留路径，不做文本提取
    │     → context.py:257 _build_user_content()
    │       读取磁盘文件 → base64 编码 → 构造 image_url vision block
    │       发给 LLM provider 的多模态接口
    │
    ├─ 文档 (pdf/docx/xlsx/pptx/txt/md/csv/json/xml/html/yaml/toml/ini/cfg)
    │     → extract_text(path) 提取文本
    │     → 追加到消息内容: "[File: xxx]\n<提取的文本>"
    │     → 最大 200,000 字符，超出截断
    │
    └─ 超大文件 (>50MB)
          → 跳过，记录 warning 日志
```

### 各文档类型的解析方式

| 文件类型 | MIME | 解析函数 | 依赖库 | 提取策略 |
|---------|------|---------|--------|---------|
| `.pdf` | `application/pdf` | `_extract_pdf()` | `pypdf` | 逐页提取文本，分页标记 |
| `.docx` | `...wordprocessingml.document` | `_extract_docx()` | `python-docx` | 提取所有非空段落 |
| `.xlsx` | `...spreadsheetml.sheet` | `_extract_xlsx()` | `openpyxl` | 逐 sheet 逐行，tab 分隔 |
| `.pptx` | `...presentationml.presentation` | `_extract_pptx()` | `python-pptx` | 逐 slide，递归收集 shape/表格文本 |
| `.txt` `.md` `.csv` 等 | `text/*` `application/json` 等 | `_extract_text_file()` | 无（标准库） | UTF-8 读取，latin-1 fallback |

所有文档解析库均使用**延迟导入**（lazy import），避免启动时加载 ~25MB 的解析库。

### 图片的特殊处理

图片**不走文本提取**，而是走多模态视觉通道：

1. `extract_documents()` 将图片路径放入 `image_paths` 列表返回
2. `context.py:257 _build_user_content()` 读取磁盘文件，重新 base64 编码
3. 构造 `{"type": "image_url", "image_url": {"url": "data:image/...;base64,..."}}` 
4. 与文本内容一起组成多模态消息发给 LLM provider

### 支持上传的完整 MIME 白名单

**图片**（websocket.py:229）：
- `image/png`, `image/jpeg`, `image/webp`, `image/gif`

**视频**（websocket.py:236）：
- `video/mp4`, `video/webm`, `video/quicktime`

**文档**（websocket.py:242）：
- `application/pdf`
- `application/vnd.openxmlformats-officedocument.wordprocessingml.document` (.docx)
- `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` (.xlsx)
- `application/vnd.openxmlformats-officedocument.presentationml.presentation` (.pptx)
- `text/plain`, `text/markdown`, `text/csv`
- `application/json`, `application/xml`, `text/html`
- `text/yaml`, `application/x-yaml`
- `application/toml`, `text/x-toml`
- `text/x-ini`, `text/x-config`

### 关键文件

| 文件 | 职责 |
|------|------|
| `webui/src/hooks/useDocuments.ts` | 前端文档附件生命周期管理，base64 编码 |
| `webui/src/hooks/useAttachedImages.ts` | 前端图片附件管理 + `DOCUMENT_MIMES` 白名单定义 |
| `webui/src/components/thread/ThreadComposer.tsx` | 合并图片/文档，构造 WebSocket 发送载荷 |
| `nanobot/channels/websocket.py` | 接收 base64，校验 MIME/大小，落盘 |
| `nanobot/agent/loop.py` | Agent Loop 预处理入口 `_prepare_message_media()` |
| `nanobot/utils/document.py` | 核心解析逻辑，按文件类型分发到对应解析器 |
| `nanobot/agent/context.py` | `_build_user_content()` 构造图片 vision block |

### 与 Skill/MCP 工具方式的对比

| 维度 | 代码内预处理（当前方式） | Skill / MCP 工具 |
|------|--------------------------|------------------|
| 触发方式 | 自动，每条消息都走 | LLM 主动决定调用 |
| LLM 是否感知 | 不感知，只看到提取后的文本/vision block | 感知，会生成 tool_use 调用 |
| 可配置性 | `channels_config.extract_document_text` 开关 | 可按需注册/卸载 |
| 解析失败时 | 静默跳过或返回 `[error: ...]` 标记 | LLM 可以看到错误并尝试重试 |
| 执行时机 | 消息入队前（预处理阶段） | Agent 运行中（工具调用阶段） |

### 配置开关

```json
// ~/.nanobot/config.json
{
  "channels": {
    "extract_document_text": true  // 默认 true；设为 false 则只传 [Attachment: path] 引用
  }
}
```

关闭后，非图片附件仅以 `[Attachment: xxx.docx]` 引用的形式追加到消息中，LLM 需要主动使用 `read_file` 工具才能读取内容。
